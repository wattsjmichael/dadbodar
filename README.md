# Dadbod AR — image-target proof of concept

One label, one animated owl, rear camera, mobile browser. No app installation or QR code.
This is a runnable source project, not the future brand-upload platform.

## Quick start

Install **Node.js 22 LTS or newer** (includes npm). Unzip this project, open a terminal
in `dadbod-ar`, then run:

```sh
npm install
npm run check
npm run dev
```

`npm run dev` starts the official example's Webpack development server on HTTPS port
**8080**, listening on your network. Open `https://localhost:8080/` on the computer.
Desktop shows a phone-testing message. Camera access starts only after **START AR**.

The generated development certificate is not automatically trusted by phones.
For the actual camera test, complete the HTTPS setup below first. Do not rely on
clicking past a certificate warning: that does not reliably enable mobile cameras.

## First physical test: included sample

Print `image-targets/dadbod-test-can_cropped.jpg` on matte paper, preserving its aspect
ratio. This is the official example's jellyfish target crop, renamed to
`dadbod-test-can` — it is not beer artwork. The matching generated data is included.
A second screen displaying that crop can also be a quick test, but reflections and
screen glare can hurt detection. No target generation is necessary for this sample.

On your phone, open the trusted HTTPS network URL, tap **START AR**, allow camera
access, and point the rear camera at the print. Move slowly until **FOUND IT** appears.
A flapping owl should fly out from the image and hover. Move the phone sideways
to check that the owl stays attached. Move the image out of view: the owl must hide
and the status must return to **LOOK FOR THE LABEL**. Bring it back to reacquire.

## Replace the sample with your beer label

1. Put your flat, front-facing artwork in:

   ```text
   image-targets/source/first-beer-label.jpg
   ```

   PNG also works. Use original artwork or a sharp, evenly lit photograph of a flat
   label. Avoid using a perspective photograph of an entire can as flat artwork.

2. From the project root, run the current official interactive generator:

   ```sh
   npx @8thwall/image-target-cli@latest
   ```

3. Answer its prompts:

   | Prompt | First flat-label test |
   | --- | --- |
   | Image file | `image-targets/source/first-beer-label.jpg` |
   | Image type | `flat` |
   | Default crop | `Y` initially; inspect the resulting crop |
   | Output folder | `image-targets/generated` (use an empty folder) |
   | Target name | `dadbod-test-can` |

   The CLI crops the trackable area to its supported 3:4 region (or rotated landscape
   equivalent). Check `dadbod-test-can_cropped.*` to see what the camera must see.
   If the automatic crop removes the distinctive artwork, regenerate with a custom crop.

4. Copy **all generated files**, including the JSON and luminance image, from
   `image-targets/generated/` directly into `image-targets/`, replacing the sample.
   Keep the names generated by the CLI. Do not copy just the JSON.

   Windows PowerShell:

   ```powershell
   Copy-Item .\image-targets\generated\* .\image-targets\ -Force
   ```

   macOS/Linux:

   ```sh
   cp image-targets/generated/* image-targets/
   ```

   The result will contain:

   ```text
   image-targets/dadbod-test-can.json
   image-targets/dadbod-test-can_original.jpg
   image-targets/dadbod-test-can_cropped.jpg
   image-targets/dadbod-test-can_thumbnail.jpg
   image-targets/dadbod-test-can_luminance.jpg
   ```

   The extension follows the source format; PNG input produces PNG assets. For example,
   the JSON `imagePath` must be `image-targets/dadbod-test-can_luminance.png` for PNG.
   It is a browser URL relative to the page, not relative to the JSON file.
   The source and staging folders are excluded from production output.

5. Run `npm run check`, restart the development server, and reload the phone page.
   Replacing the artwork alone does not update the tracker; regenerate its data too.
   On a later generation, use a new empty output folder; the CLI refuses overwrites
   by default. Keep backups of any label data you want to retain.

## Configuring the target name

The JSON's `name` is the single source of truth. `src/app.js` imports
`../image-targets/dadbod-test-can.json`, sends that data to
`XR8.XrController.configure({imageTargetData: [target]})`, and sets the official
`xrextras-named-image-target` entity's `name` to `target.name`.

Keep `dadbod-test-can` for this sprint. If you rename the JSON file itself, change
its import in `src/app.js` and the file path in `scripts/check-target.cjs`.
If you only change the internal name, the anchor follows automatically.

## Cylindrical cans and bottles

After the flat print works, regenerate from the **unwrapped artwork** and choose
`cylinder` in the same CLI. Supply the real container circumference and the physical
width covered by the artwork, using consistent units. For a partial wrap, the artwork
width is less than the circumference. Use `cone` only for genuinely tapered packaging
and supply the prompted geometry measurements.

Copy the new generated files into the same directory. Keep all generated `type` and
`properties` values intact. The application accepts PLANAR, CYLINDER and CONICAL data;
it does not replace geometry with a flat marker. The official component owns target
position, orientation, scale and visibility for each type. A geometry listener moves
the owl outside the cylinder/cone surface. No tracking rewrite is needed.

Glossy metal, glare, repeated patterns, sparse artwork, steep viewing angles, motion
blur and a hand covering the crop can prevent tracking. Test one front-facing can
under diffuse light first, then slowly rotate it. Cylindrical tracking and its content
placement still require physical validation; do not treat flat-print success as proof
of reliable 360-degree can tracking.

## Testing a phone on the same network — trusted HTTPS

Camera APIs require a secure context. `http://192.168.x.x:8080` on a phone is not
sufficient, and `localhost` on your phone means the phone itself.

1. Connect the computer and phone to the same Wi-Fi. Avoid guest networks with client
   isolation. Allow Node.js through Windows Firewall on **Private networks** when asked.
2. On Windows run `ipconfig` and find the Wi-Fi adapter's IPv4 address. The commands
   below use **192.168.1.42** as an example; replace it with your actual address.
3. Install `mkcert` using its [official instructions](https://github.com/FiloSottile/mkcert#installation).
   Then, in the project folder:

   ```sh
   mkcert -install
   mkdir certs
   mkcert -key-file certs/dev-key.pem -cert-file certs/dev.pem localhost 127.0.0.1 192.168.1.42
   mkcert -CAROOT
   ```

4. Copy **only `rootCA.pem`** from the directory shown by `mkcert -CAROOT` to your own
   test phone. Never share `rootCA-key.pem` or commit certificate private keys.
   This local CA lets your phone trust the development certificate:

   - **iPhone:** install the downloaded certificate profile in Settings → General →
     VPN & Device Management; then enable it under General → About → Certificate
     Trust Settings. Open the site directly in Safari.
   - **Android:** install it as a CA certificate through Settings → Security/Privacy →
     Encryption & credentials → Install a certificate (wording varies by device).
     Open the site directly in Chrome.

5. Restart the server so it loads `certs/dev.pem` and `certs/dev-key.pem`:

   ```sh
   npm run dev
   ```

6. Type `https://192.168.1.42:8080/` into the phone browser, using your actual IP.
   Confirm the connection is trusted, tap START AR, and allow camera access. If your
   computer's IP changes, regenerate the certificate for the new address. Remove the
   development CA from the phone when you no longer need this workflow.

Alternatively, serve the production `dist/` directory from static hosting with a
valid HTTPS certificate and open that URL. No 8th Wall Cloud project, app key, domain
registration with 8th Wall, subscription, login, or QR scanning is used by this app.

## Production build

```sh
npm run check
npm run build
```

Upload the **entire contents** of `dist/` to HTTPS static hosting, preserving folders.
It works at the origin root or a directory URL ending in `/`. Serve JavaScript with
an appropriate JavaScript MIME type and preserve engine resource files. A single
`index.html` upload is insufficient. Webpack's size warnings come from the supplied
engine resources; they are not build errors. AR libraries load after START AR.

For a local production smoke check, `npm run dev` is the development server; do not
open `dist/index.html` directly as a `file://` URL for AR.

## How it works

- `src/app.js`: start gate, local-engine loading, capability check, single target
  configuration, scene construction, status and permission/error handling.
- `src/styles.css` and `src/index.html`: start screen and camera overlay.
- `image-targets/`: active generated target JSON and every generated associated asset.
- `image-targets/source/`: source artwork; not deployed.
- `public/models`, `public/textures`, `public/audio`: empty optional asset folders.
- `external/`: unmodified runtime files supplied with the official example. The
  application loads local 8Frame, XRExtras and the distributed XR engine. No hosted
  8th Wall Cloud API is used. Keep engine chunks and license notices together.
- `config/`: official-example Webpack tooling, with local HTTPS and static asset copying.
- `scripts/check-target.cjs`: checks names, supported geometry and local asset references.

The anchor is the official `xrextras-named-image-target` component. It copies the
engine's target position, quaternion and scale on `xrimagefound` / `xrimageupdated`,
and hides itself on `xrimagelost`. App listeners update LOOK FOR THE LABEL / FOUND IT
and start/reset the owl animation. The +Z offset places the object in front of the
planar label. For curved targets it includes the target's middle radius.

Switching away from the tab pauses XR8 and hides stale content. Returning resumes
scanning. STOP AR and page navigation stop the engine. Permission denial, absent
camera support, incompatible devices, missing assets, loading failures and runtime
errors produce a readable recovery screen. A 90-second startup timeout offers reload
if initialization or a permission prompt stalls.

## Verification and limits

See `VALIDATION.md` for checks performed on this build. The physical iPhone Safari,
Android Chrome and real-can tests are the remaining acceptance gate. There is no
